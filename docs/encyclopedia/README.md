# Resale encyclopedia — how it works

Dylan's instructions (Oct 12 2026): research everything we see, including what we pass on, and write it down per item
type. Cover makers, brands, marks, finishes, materials, quality tells, nuances, variants and sold prices, so the knowledge
compounds into a database of easy-to-find information. It is also what Dylan quotes to buyers when he sells, so be
complete and accurate. Taking longer per item is fine. The encyclopedia is for **speed and knowledge, never a filter**:
a type with no entry gets researched, not skipped.

## Files
- `entries/<slug>.md`: one file per item type. This is the source of truth. Slugs are plural, lowercase and hyphenated.
  `entries/_aliases.json` maps old or duplicate slugs to the current one.
- `index.md`: one row per entry (type, slug, value summary, buy rule, updated). It is generated by `scripts/enc.py index`.
- In the claude.ai project the entries are bundled into `encyclopedia/encyclopedia-<letters>.md` volumes, generated by
  `scripts/enc.py volumes`. Never edit the volumes; edit the entries.
- From any chat without the repo, read
  `https://raw.githubusercontent.com/dylanpetty378-arch/game-platform/refurbish/docs/encyclopedia/entries/<slug>.md`.

## Tool
`python3 scripts/enc.py find <words>` · `show <slug>` · `seen <slug> "<line>"` · `add <file.md>` (adds new entries, or
appends to existing ones as "Additional research") · `index` · `sync` (writes the type rubric into `db/item_types.jsonl`) ·
`lint` (lists missing sections or rubric fields).

## Entry template (every section required; write "unknown" rather than skipping one)
````
# <Type name> (<main makers/brands in brackets>)
Updated: YYYY-MM-DD · Sources: <every source used: eBay sold searches, Terapeak, auction archives, collector sites, price guides — with URLs>
Slug: <slug> · Aliases: <other names sellers use>
Summary: <one line: what sells for what — the tiers in $>
Buy rule (short): <one line>

## What it is / how to recognise it in a photo
Shape, size, materials, construction, period. Where the maker's mark/signature/hallmark/serial sits and what it looks like.
Words sellers put in titles. How to tell it from look-alikes.

## Makers, brands and variants
Each maker/brand/line that matters: years, marks, what the line is known for, relative value. Rare variants/colours/
finishes/sizes that multiply the price.

## Materials, finishes and quality tells
Solid vs plated vs filled, hand-made vs moulded/transfer, period finish vs refinish, weight, tool marks, signs of quality
and of cheap production. How to tell old from new (wear patterns, construction, marks that changed over time).

## Condition, damage and repairs
What damage is common, what kills value, what's acceptable, how repairs and restorations show up in photos, what to ask.

## Fakes, reproductions and reissues
Known repros/fakes and how to spot them.

## Comps (sold, dated)

## Market
How often it sells, how fast, where it sells best, who buys it (collectors, decorators, users), seasonality, trend.

## What sellers usually miss
The tells that raise the price and that untrained sellers leave out of titles.

## Shipping / handling
Weight, packing, typical shipping cost, fragility notes.

## Selling it (for the buyer-facing listing)
What buyers want to know: key facts to state, measurements to give, marks to photograph, keywords for the title.

## Buy rule

both ways (Dylan's rule). Must fit a passenger seat.
````

## Process for a review session
1. For every flagged listing, name the type and look it up (`enc.py find`).
2. If the type has an entry: apply its tells and buy rule; append a "Seen in sweeps" line (`enc.py seen`).
3. If there is no entry, or the item is a variant the entry doesn't cover: research it fully and write or extend the
   entry, using `enc.py add` for drafts written elsewhere. Do this for passes too: the passes are knowledge.
4. Run `enc.py index && enc.py sync`, then commit.
